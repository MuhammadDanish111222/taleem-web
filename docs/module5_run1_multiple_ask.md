# Multiple Ask — web boundary and solved-paper UI

When enabled, the Multiple Ask student page uses same-origin BFF routes under `/api/ai/multiple-ask/`. The BFF verifies Firebase identity and uses a short-lived internal JWT to call the private service. It never exposes a service role, provider key, Railway URL, storage credential, raw source, private object key, signed URL, embedding, or provider payload.

Session-create and pasted-text contracts require `boardId`, `classId`, `subjectId`, and optional `chapterId`, using bounded safe identifiers. These immutable values are carried only in the signed BFF request and persisted by the service; finalization uses its opaque session ID and request ID.

For files, the BFF accepts metadata only and returns one short-lived direct-upload capability. The supported response contract is `PUT` plus `Content-Type` and `x-upsert: false`; it contains no service-role credential, storage credential, Railway URL, OCR key, or provider key. Image/PDF bytes go directly to the private temporary bucket and never transit Vercel or DeepSeek. The bucket must be private and pre-created by an operator; this run does not create it.

Finalization and pasted text create durable jobs. Protected polling returns safe job/item metadata, original paper order, labels, section context, the actual or corrected `questionText`, answer mode, dynamic MCQ options, structured MCQ results, safe provenance, answer blocks, topic names, visuals, counts, retention expiry, and safe terminal error codes. A correction explicitly supplies `short`, `long`, or `mcq`; MCQ supports zero options or ordered contiguous A-starting options. Source text outside the item question, uploaded bytes, private object keys, and signed URLs never appear in browser responses.

The solved-paper UI renders MCQs as MCQs (including a zero-option direct answer), marks the correct option with accessible text as well as styling, and shows Question → Answer for written items. Provenance is **Answer from book · Topic** for grounded/approved answers when a topic is safe to display, otherwise **Not from book**. Visuals render only when supplied by the safe result contract. Single Ask remains its existing typed-text-only `/api/ai/ask` feature.
